**Notes:**

- Env module: `src/sight_agent/rl/godot_env.py`. Class `GodotSignalDodgeEnv(gym.Env)`. Gymnasium 1.2.3, NumPy 2.4.4 on Python 3.14.4. `action_space = Discrete(3)`, `observation_space = Box(-1.0, 1.0, shape=(10,), dtype=float32)`. Sparse-survival reward sourced verbatim from Godot's `step_result.reward`; the env does NOT synthesize reward. `info` per plan section 6: always carries `run_id`, `episode_id`, `godot_pid`, `tcp_port`, `frame`; carries `seed` on reset; carries `terminal_reason` on step; nests Godot-supplied wire `info` under `info["godot_info"]`. Default `max_steps = 1800` (30s @ 60Hz) exposed as `DEFAULT_MAX_STEPS`.
- Lifecycle (locked, plan Decision 2): `__init__` does NOT launch Godot or open TCP -- builds spaces only and stores config. First `reset()` lazy-launches the subprocess and opens the TCP connection. One Godot process and one persistent TCP connection across all episodes; `reset()` is a soft reset through the transport. `close()` closes the transport, calls `Popen.terminate()` with a 2s grace window, then `kill()` if still alive, then `wait()`. Idempotent across multiple `close()` calls and safe before any `reset()`. Constructor errors (zero `max_steps`, non-positive timeouts) raise `ValueError`. `step()` before `reset()` raises `RuntimeError`. `step()` after terminal/truncation raises `RuntimeError` until next `reset()`. `reset()` on a closed env raises `RuntimeError`. NumPy int actions (e.g. `np.int64(1)` from SB3) coerced to plain `int` before reaching the transport.
- Godot launch contract: `cmd = [godot_executable, "--path", project_path]` plus `--headless` when `headless=True`. Env vars injected: `SIGHT_TCP_MODE=1`, `SIGHT_TCP_PORT=<port>`, and `SIGHT_GODOT_LOG_PATH=<run_dir>/godot.ndjson` when `run_dir` is supplied (parent dir created via `mkdir(parents=True, exist_ok=True)`). Uses the existing `SIGHT_GODOT_LOG_PATH` env var honored by `games/signal-dodge/scripts/logger.gd`; no new CLI arg or GDScript change. Connect retry loop bounded by `connect_timeout_s` with 100ms intervals and 500ms per-attempt TCP timeout; surfaces `GodotTransportError` on overall timeout. Transport / protocol / remote exceptions propagate from `reset` and `step` unchanged per plan section 5.
- Test seams: `transport_factory(run_id, host, port, recv_timeout_s)` and `process_factory(cmd, env, stdout, stderr)` are constructor-injected. `tests/rl/test_h3_godot_env.py` covers 25 cases via `FakeTransport` (FIFO-queued `reset_ok` / `step_result` / raisable exceptions, configurable `connect_attempts_to_succeed`) and `FakeProcess` (`pid` / `poll` / `terminate` / `kill` / `wait`, `simulate_terminate_hangs` to exercise the SIGKILL fallback).
