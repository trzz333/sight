**Notes:**

- Python NDJSON evidence (new, opt-in): when `run_dir` is supplied, the env opens `<run_dir>/python.ndjson` lazily on first `_ensure_process_and_transport` and closes it in `env.close()`. One JSON object per line, UTF-8, per-event flush via inline `_NdjsonWriter`. Event types: `env_start` (logged once after first launch+connect+hello), `reset` (with `episode_id`, `seed`, `frame`, `terminated`, `truncated`), `step` (with `episode_id`, `frame`, `reward`, `terminated`, `truncated`, `terminal_reason`), `close`, and `error` (with `where` in {"launch", "connect", "reset", "step"}, `kind`, `message`, plus context like `episode_id` / `seed` on reset failures). Every line is decorated with `run_id`, `godot_pid`, `tcp_port`, and `ts_unix`. `run_dir=None` keeps the writer at None and `_log_event` is a strict no-op so existing callers see zero behavior change.
- Early-exit detection (new): `_launch_godot` now records the launch cmd into `self._launch_cmd` before invoking the process factory. `_connect_transport` calls `_raise_if_godot_exited()` before each connect attempt and after each failed attempt. When `self._proc.poll()` returns a non-None exit code, raises `GodotTransportError` with a distinct message containing exit code, full launch cmd, and the port being waited on -- explicitly different from the connect-timeout variant ("not reachable within ...") so operators can tell process death from listener-not-ready at a glance. The `error` NDJSON event logged for this case carries `where="connect"` because that is where the env caught it; the message text reveals the underlying cause. `env_start` is NOT logged when connect never succeeds.
- Tests added: `tests/rl/test_h3_godot_env.py` gains 6 cases. (1) `python.ndjson` written under `run_dir` with `env_start`/`reset`/`step`/`close` in order plus full identity decoration. (2) `python.ndjson` omitted when `run_dir` is None. (3) `error` event logged with `where="reset"` plus `episode_id` and `seed`. (4) `error` event logged with `where="step"`. (5) early subprocess exit raises `GodotTransportError` whose message includes exit code (42), port (8765), and cmd (`godot.exe`), and is NOT the connect-timeout variant. (6) early-exit `error` event logged when `run_dir` is supplied; `env_start` correctly absent. `FakeProcess.set_exit_code(code)` test seam added so the early-exit path can be exercised without launching anything.
- Behavior unchanged: transport / protocol / remote exceptions still propagate unchanged from `reset` and `step` per plan section 5; `close()` still idempotent with terminate -> 2s grace -> kill fallback; spaces unchanged (`Discrete(3)` and `Box(-1, 1, (10,), float32)`); reward semantics unchanged; lazy-launch lifecycle unchanged. `_log_event` is wrapped to swallow all writer errors so logging failures cannot break the env.
